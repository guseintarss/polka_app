# ПОЛКА: тестирование на телефоне

Приложение опубликовано и доступно тестерам по HTTPS:

**<https://guseintarss.github.io/polka-app/>**

![QR-код на приложение](tester-qr.png)

Ссылка публичная. Данные каждого тестера остаются только на его устройстве:
аккаунтов и облака нет, автоматической аналитики нет. Приложение считает
локальные счётчики действий, а отчёт тестер отправляет сам — по кнопке.
Данные о товаре по штрихкоду можно найти в открытых базах Open Food Facts
и Open Products Facts — тоже только по нажатию кнопки или после разового
разрешения, наружу уходит только код.

## Готовое сообщение тестерам

Скопируйте текст ниже и отправьте вместе со ссылкой или QR-кодом.

```text
Помогите протестировать приложение ПОЛКА — кухонный журнал для телефона.
Это PWA: устанавливается на домашний экран, работает офлайн, данные остаются
только на вашем телефоне.

Ссылка: https://guseintarss.github.io/polka-app/

Установка:
• iPhone: откройте ссылку в Safari → «Поделиться» → «На экран “Домой”» → «Добавить».
• Android: откройте ссылку в Chrome → меню «⋮» → «Установить приложение»
  (или «Добавить на главный экран»).
Если ссылка открылась внутри Telegram/WhatsApp, сначала нажмите «⋯» →
«Открыть в Safari» (iPhone) или «Открыть в Chrome» (Android).

Что сделать (15–20 минут):
1. Установите приложение и откройте его с домашнего экрана.
2. Полка: добавьте продукт вручную и, если удобно, сканированием штрихкода
   или QR (кнопка «Сканировать»); для нового кода нажмите «Найти в открытых
   базах» — приложение один раз спросит разрешение и подставит название.
   Попробуйте «Сканировать подряд»: наведите камеру на несколько кодов —
   продукты должны добавляться сами. Попробуйте поиск, изменение и удаление
   с отменой.
3. Рецепты: откройте фильтр «Можно готовить», зайдите в «Карри с нутом»,
   поменяйте порции, добавьте недостающее в покупки, нажмите «Готовить»
   и отмените.
4. В карточке рецепта откройте ссылки «Источник» и «Видео» — они должны
   открываться в браузере, а не внутри приложения.
5. План: соберите план на неделю, замените одно блюдо, нажмите
   «Собрать покупки».
6. Покупки: отметьте позиции, купите отмеченное и отмените, попробуйте
   «Поделиться списком».
7. Ещё: посмотрите статистику, откройте «Аналитика использования» и нажмите
   «Отправить отчёт» — так я увижу, что приложение пригодилось.
8. Офлайн: включите авиарежим, откройте установленное приложение, добавьте
   продукт, выключите авиарежим и проверьте, что данные сохранились.

Пришлите, пожалуйста, ответы:
• Телефон, версия ОС, браузер.
• Установка прошла? Что было непонятно?
• Что понравилось и что раздражало?
• Были ли зависания, пустые экраны, обрезанный текст? Скриншот приветствуется.
• Заработал ли офлайн-режим?
• Получилось ли сканировать штрихкод или QR? Нашлось ли название по коду?
  Получилось ли отправить отчёт?
• Оценки от 1 до 5: установка, скорость, понятность, полезность.
• Стали бы пользоваться? Чего не хватает?
```

## Установка

### iPhone / Safari

1. Откройте <https://guseintarss.github.io/polka-app/> в Safari.
2. Нажмите «Поделиться» (квадрат со стрелкой вверх).
3. Прокрутите меню и выберите «На экран “Домой”».
4. Название «ПОЛКА» → «Добавить».
5. Запускайте приложение с иконки на домашнем экране.

Если пункта «На экран “Домой”» нет — ссылка открыта не в Safari или включён
режим инкогнито. Скопируйте ссылку и откройте её в обычном Safari.

### Android / Chrome

1. Откройте <https://guseintarss.github.io/polka-app/> в Chrome.
2. Меню «⋮» → «Установить приложение» (в некоторых версиях —
   «Добавить на главный экран»).
3. Подтвердите установку и запускайте с иконки.

В приложении также есть раздел «Ещё» → «Установка» с подсказкой
для текущего устройства.

## Проверка офлайн-режима

1. Откройте установленное приложение онлайн и дайте ему загрузиться.
2. Включите авиарежим (или выключите Wi-Fi и мобильный интернет).
3. Откройте приложение с домашнего экрана — появится баннер «Офлайн»,
   но полка, рецепты, план и покупки останутся доступны.
4. Добавьте продукт или отметьте покупку, перезагрузите приложение —
   изменения должны сохраниться.
5. Выключите авиарежим: при следующем запуске приложение снова выйдет
   в сеть, данные не потеряются.

## Сценарии для тестеров

| № | Сценарий | Что проверить |
|---|---|---|
| 1 | Первый запуск | Понятно ли с первых секунд, что это и с чего начать |
| 2 | Полка | Добавление, поиск, фильтры, срок годности, правка, удаление и «Отменить» |
| 3 | Сканер и поиск по коду | Кнопка «Сканировать»: разрешение камеры, штрихкод и QR, подстановка названия и кода. Для нового кода — «Найти в открытых базах»: разовое согласие, название из базы, повторный поиск без сети. «Сканировать подряд»: несколько кодов за один заход, повторы пропускаются, «Отменить последнее» работает |
| 4 | Рецепты | Фильтр «Можно готовить», иллюстрации блюд, карточка, порции, нехватка, «Готовить» |
| 5 | Источник и видео | Открываются только по тапу, во внешнем браузере; внутри нет видео и превью |
| 6 | План | Сборка плана, замена блюда, настройки порций/диеты/времени |
| 7 | Покупки | Добавление, отметки, «Купить отмеченное», «Поделиться списком» |
| 8 | Ещё | Статистика, экспорт JSON, установка, очистка данных |
| 9 | Аналитика | «Ещё» → «Аналитика использования»: сводка, «Отправить отчёт», «Скачать JSON» |
| 10 | Офлайн | Открытие без сети, сохранение данных после перезапуска |
| 11 | Общее | Скорость, понятность текстов, размер тач-целей, тёмная тема ОС |

## Данные и приватность

- Всё состояние хранится в `localStorage` устройства, ключ `polka.kitchen.v1`.
- Нет регистрации, серверов, синхронизации, рекламы и автоматической
  аналитики. Счётчики действий хранятся на устройстве, ключ
  `polka.analytics.v1`; отчёт уходит только когда тестер нажмёт
  «Отправить отчёт».
- Камера используется только в сканере и только по кнопке; видео никуда
  не передаётся и не сохраняется.
- Удаление приложения удаляет его данные; перед очисткой внутри приложения
  («Ещё» → «Данные» → «Очистить кухню») можно сделать экспорт JSON.
- Ссылки на источник и видео рецепта открываются во внешнем браузере только
  по явному тапу. Приложение не загружает внешние страницы, видео и превью.
- Название по штрихкоду запрашивается у открытых баз Open Food Facts
  (world.openfoodfacts.org) и Open Products Facts
  (world.openproductsfacts.org) — по кнопке «Найти в открытых базах» или
  после разового разрешения в конвейере: наружу уходит только штрихкод.
  Найденное запоминается на устройстве, и повторный поиск того же кода
  работает без сети. Согласие спрашивается один раз — при первом нажатии
  или в шторке «Сканировать подряд». Забыть сохранённые коды и разрешение
  можно на экране «Ещё» в строке «Память поиска по коду».
- Демо-данные можно вернуть в «Ещё» → «Данные» → «Демо-кухня».

## Ограничения версии

- Нет аккаунтов и облачной синхронизации: данные живут на одном устройстве.
- Цены и каталог демонстрационные, без онлайн-обновления.
- Сканер работает по HTTPS и требует разрешения камеры; декодер ZXing
  хранится в приложении и доступен офлайн.
- Аналитика не отправляется автоматически: отчёт формируется на устройстве
  и отправляется тестером вручную.
- Данные о товаре по штрихкоду подтягиваются из Open Food Facts и Open
  Products Facts по кнопке или после разового разрешения; российских товаров
  в базах может не хватать — название всегда можно вписать вручную.
- Нет push-уведомлений и фоновых задач.
- Установка в App Store и Google Play не входит в эту версию.
- На iOS система может очистить хранилище редко используемого PWA, если
  приложение не добавлено на домашний экран. Регулярный экспорт JSON —
  страховка.

## Для организатора: как приходят отчёты

Тестеры нажимают «Ещё» → «Аналитика использования» → «Отправить отчёт» и
отправляют текст через Telegram, почту или заметки. В отчёте только счётчики:
запуски, открытия экранов, добавления, сканирования, поиски по коду,
приготовления. Названий
продуктов, цен и личных данных в нём нет. Для машинной обработки тестер может
скачать JSON (`polka-analytics-<дата>.json`). Если тестер нажмёт «Сбросить
счётчики», история на устройстве удалится.

## Для организатора: обновление публикации

Публикация — репозиторий <https://github.com/guseintarss/polka-app>
(ветка `main`, GitHub Pages из корня). В репозиторий попадает только
собранный дистрибутив без тестов и служебных файлов.

После правок в `polka_app`:

```bash
tools/deploy-pages.sh
```

Скрипт собирает `dist/polka-app`, копирует изменения в репозиторий, ждёт
сборку GitHub Pages и проверяет URL. Если менялись кэшируемые файлы
(`css/`, `js/`, `assets/`, `index.html`), перед публикацией поднимите
`VERSION` в `sw.js` — иначе тестеры получат старый кэш.

Проверки перед публикацией:

```bash
node tests/engine.test.js
node tests/lookup.test.mjs

NODE_PATH=/path/to/node_modules \
CHROME_PATH=/path/to/chrome \
AXE_PATH=/path/to/axe-core/axe.min.js \
node tests/e2e.mjs

# тот же E2E, но против опубликованного приложения
BASE_URL=https://guseintarss.github.io/polka-app/ \
CHROME_NO_PROXY=1 \
NODE_PATH=/path/to/node_modules \
CHROME_PATH=/path/to/chrome \
AXE_PATH=/path/to/axe-core/axe.min.js \
node tests/e2e.mjs
```

`CHROME_NO_PROXY=1` нужен, если в системе настроен прокси и Chromium не
открывает внешний URL напрямую.

Пересобрать QR-код после смены адреса:

```bash
qrencode -t PNG -o docs/tester-qr.png -s 8 -m 2 'https://guseintarss.github.io/polka-app/'
qrencode -t SVG -o docs/tester-qr.svg -s 8 -m 2 'https://guseintarss.github.io/polka-app/'
```

Если репозиторий или адрес изменятся, задайте их для скрипта через переменные
`POLKA_PAGES_REPO` и `POLKA_PAGES_URL` или поправьте значения по умолчанию
в `tools/deploy-pages.sh`.
