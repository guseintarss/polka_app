# ПОЛКА — приложение для телефона

Мобильное PWA кухонного журнала **ПОЛКА**: полка, рецепты, план на неделю и
список покупок. Отдельный интерфейс для телефона, то же ядро, что у сайта
[`../polka`](../polka).

Приложение устанавливается с сайта на iPhone и Android, работает офлайн и
хранит данные только на устройстве. Без аккаунтов и облака. Наружу ничего не
уходит само по себе: отчёт аналитики отправляется только по кнопке, а данные
о товаре по штрихкоду запрашиваются по кнопке или после разового разрешения —
и только сам код.

## Что умеет

- **Полка.** Продукты с количеством, категорией, зоной хранения, сроком и ценой.
  Поиск, фильтры, группировка, предупреждения о сроках, автоподстановка из
  каталога. Добавление сканированием штрихкода или QR через камеру телефона:
  код сохраняется в карточке, знакомые коды подставляют название сами. Для
  нового кода — кнопка «Найти в открытых базах»: название, бренд и объём
  приходят из Open Food Facts и Open Products Facts (уходит только код)
  и запоминаются на устройстве. Режим «Сканировать подряд» добавляет продукты
  конвейером: камера не закрывается, каждый новый код сразу попадает на полку,
  повторы пропускаются, последний продукт можно отменить.
- **Рецепты.** 27 блюд с локальными иллюстрациями, поиск и фильтры, процент
  совпадения с полкой, нехватка, порции, стоимость, шаги. У трёх рецептов есть
  ссылка на источник и видео-инструкцию — они открываются только по тапу
  во внешнем браузере. Готовка списывает продукты и показывает отмену.
- **План.** 7 дней, завтрак/обед/ужин, замена и удаление блюд, настройки
  порций/диеты/времени, сборка плана, недостающее и смета.
- **Покупки.** Список из плана, рецептов и вручную, без дублей. Отметки,
  перенос купленного на полку, очистка, сумма и отправка списка.
- **Ещё.** Статистика спасённых продуктов, настройки, экспорт/импорт JSON,
  демо, очистка, установка приложения. Аналитика использования: локальные
  счётчики действий и отчёт, который отправляется по кнопке.
- **PWA.** Установка на домашний экран, офлайн-кэш, обновление без потери
  данных, safe-area, нижняя навигация, шторки с закрытием жестом и кнопкой
  «назад».

## Запуск

Нужен HTTP-сервер: ES-модули и service worker не работают по `file://`.

```bash
cd polka_app
python3 -m http.server 8766 --bind 127.0.0.1
```

Откройте <http://127.0.0.1:8766/>. Для установки на телефон нужен HTTPS
(или `localhost` при отладке).

```bash
tools/serve.sh          # порт 8766
tools/serve.sh 9000     # другой порт
```

## Установка на телефон

- **Готовое приложение:** <https://guseintarss.github.io/polka-app/>.
- **Android / Chrome:** меню → «Установить приложение» или «Добавить на главный
  экран». В приложении кнопка установки есть в разделе «Ещё».
- **iPhone / Safari:** «Поделиться» → «На экран Домой». Safari не показывает
  `beforeinstallprompt`, поэтому в «Ещё» есть инструкция.
- После установки приложение открывается без адресной строки и работает без
  сети.

## Проверки

```bash
node tests/engine.test.js
node tests/lookup.test.mjs
node tests/images.test.mjs
```

43 теста ядра: сроки, совпадение рецептов, план, покупки, статистика,
нормализация импорта и штрихкодов, защита от повреждённых данных, разбор
отсканированных кодов и контракт внешних источников рецептов.

16 тестов поиска по коду: нормализация кода, согласие, память до 200 записей
с вытеснением старых, цепочка Open Food Facts → Open Products Facts,
обработка 404, 500 и обрыва сети. Сеть не нужна — `fetch` подменяется.

4 теста иллюстраций: у каждого рецепта есть своя локальная SVG-картинка
в палитре приложения, без активного содержимого.

E2E на мобильном вьюпорте (Playwright, dev-зависимость не входит в приложение):

```bash
NODE_PATH=/path/to/node_modules \
CHROME_PATH=/path/to/chrome \
AXE_PATH=/path/to/axe-core/axe.min.js \
node tests/e2e.mjs
```

Скриншоты складываются в `tests/screenshots/`. E2E выполняет 20 проверок:
пять разделов на 390×844 и 320px, manifest и service worker, доступность
(axe, WCAG AA), отсутствие горизонтального переполнения, навигацию,
офлайн-перезагрузку и UI-сценарии:

- полка: ручная категория и зона хранения, правка, удаление, отмена и Back;
- рецепт: сброс и сохранение порций, готовка с отменой, недостающее в покупки;
- рецепт: источник и видео открываются только по ссылке, без встроенных медиа
  и автоматических внешних запросов;
- план: очистка с отменой, открытие слота, замена, сборка и синхронизация;
- покупки: покупка и очистка с отменой, отправка списка;
- данные: экспорт JSON и импорт файла через интерфейс;
- сканер: QR подставляет название, штрихкод запоминается и подставляется
  в следующий раз (фейковая камера Chromium; нужны `qrencode` и `ffmpeg`,
  иначе проверки сканера пропускаются);
- конвейер: несколько кодов подряд без закрытия камеры, согласие внутри
  шторки, повторы пропускаются, «Отменить последнее» убирает продукт;
  фоновый поиск не затирает правки, сделанные до ответа базы, и не теряет
  фокус на полке;
- поиск по коду: без нажатия запросов нет, согласие можно отклонить — запроса
  не будет; найденное подставляется и запоминается, повторный поиск того же
  кода идёт из памяти; 404 — «не найдено», 500 и офлайн — понятные сообщения;
  цепочка OFF → Open Products Facts проверяется отдельно; память поиска
  сбрасывается на экране «Ещё» (ответы баз подменяются в тесте);
- рецепты: у каждой карточки и у hero-блока своя локальная иллюстрация,
  внешних запросов за картинками нет;
- аналитика: счётчики пишутся локально, отчёт скачивается и не содержит
  названий продуктов и цен.

Тот же набор проверок работает против опубликованного приложения: задайте
`BASE_URL=https://guseintarss.github.io/polka-app/` (обязательно со слэшем
в конце) при запуске `tests/e2e.mjs`. Тест сам открывает удалённый URL,
проверяет manifest, service worker, установку, офлайн-перезагрузку и не
должен обращаться к внешним ресурсам. Если в системе настроен прокси и
Chromium не может открыть внешний URL, добавьте `CHROME_NO_PROXY=1`.

### Lighthouse

Мобильный профиль, headless Chromium, локальный сервер без сжатия:

| Категория | Оценка |
|---|---|
| Accessibility | 100 |
| Best practices | 100 |
| SEO | 100 |
| Performance | 72 (72–74 в серии) |

Производительность ограничена отказом от сборки: браузер получает
ненминифицированные CSS/JS и несколько render-blocking файлов. На реальном
хостинге с gzip/brotli и кэшированием показатель будет выше; доступность,
офлайн-контракт и отсутствие внешних запросов без согласия в этой версии
важнее минификации.

Ядро `js/data.js` и `js/engine.js` — копии из сайта. Не редактируйте их здесь:
правьте в `../polka` и запускайте `tools/sync-core.sh`, затем поднимайте
`VERSION` в `sw.js`.

## Данные

Состояние лежит в `localStorage` по ключу `polka.kitchen.v1` — тому же, что у
сайта. При размещении приложения на том же origin данные сайта подхватятся.
Перенос между устройствами — экспорт/импорт JSON в разделе «Ещё».

```js
{
  version: 1,
  settings: { servings: 2, diet: "all", maxTime: 0 },
  pantry: [{ id, ingredientId, name, qty, unit, category, storage, expires, price, barcode, addedAt }],
  plan: { "2026-10-22": { breakfast, lunch, dinner } },
  shopping: [{ id, ingredientId, name, qty, unit, checked, source, price }],
  stats: { cooked: 4, history: { "2026-10-22": { count: 1, value: 160 } } }
}
```

Приложение просит браузер защитить хранилище от автоматической очистки
(`navigator.storage.persist()`), но гарантий на iOS нет. Регулярный экспорт
JSON — единственная страховка.

## Публикация

Приложение опубликовано на GitHub Pages:
<https://guseintarss.github.io/polka-app/>. Репозиторий публикации —
<https://github.com/guseintarss/polka-app> (ветка `main`, корень репозитория).

Обновление после правок в `polka_app`:

```bash
tools/deploy-pages.sh
```

Скрипт собирает `dist/polka-app` (только файлы приложения), копирует изменения
в репозиторий, дожидается сборки Pages и проверяет URL. Если менялись
кэшируемые файлы (`css/`, `js/`, `assets/`, `index.html`), перед публикацией
поднимите `VERSION` в `sw.js` — иначе тестеры получат старый кэш.

Можно разместить приложение и на другом статическом хостинге с HTTPS:
загрузите содержимое `dist/polka-app` целиком. Относительные пути позволяют
разместить приложение и в подкаталоге (`https://example.com/polka/`).

Требования к серверу: корректный `Content-Type` для `.webmanifest`
(`application/manifest+json`) и `.js` (`text/javascript`); HTTPS обязателен для
service worker и установки.

## Ограничения

- Нет синхронизации и аккаунтов: данные живут на одном устройстве.
- Нет онлайн-цен и загрузки внешних рецептов: каталог и цены
  демонстрационные. Название и объём по штрихкоду можно найти в открытых
  базах Open Food Facts и Open Products Facts — по кнопке или после разового
  разрешения в конвейере; уходит только код. Покрытие российских товаров
  в базах неполное. Ссылки на источник и видео открываются в браузере только
  по явному тапу; приложение их не загружает. Иллюстрации блюд лежат
  в приложении и не требуют сети.
- Сканер работает по HTTPS (или localhost) и требует разрешения камеры.
  Декодер ZXing лежит в приложении и кэшируется для офлайна.
- Аналитика не отправляется автоматически: локальные счётчики действий,
  отчёт уходит только по кнопке в «Ещё» → «Аналитика использования».
- Нет push-уведомлений и фоновых задач.
- Установка в App Store / Google Play не входит в эту версию. При необходимости
  PWA можно обернуть в Capacitor без переписывания интерфейса.
